Data Flow: Hebrew ISO Document Processing
──────────────────────────────────────────

User uploads ISO9001-2015-Hebrew.pdf via iso-web
    │
    ▼
iso-api stores in corpus_files (BYTEA)
    │
    ▼
iso-doc-parse-rag /parse endpoint
    │ Calls: https://gpt-oss-20b-kserve-workload-svc.llm.svc.cluster.local:8000/v1
    │ Model: GPT-oss-20b (21B MoE, 128K context)
    │ Task: Extract Hebrew RTL clauses with structure
    ▼
GPT-oss-20b returns 94 structured clauses
    │ (vs 21 garbage clauses with regex parser)
    ▼
iso-api stores in iso_clause_text
    │ standard: ISO9001
    │ edition: 2015
    │ language: he
    │ clause_id: 1, 2, 3, 4, 4.1, 4.2, ..., 10.3 (94 total)
    │ body: Clean Hebrew RTL text
    ▼
iso-api chunks text (1000 chars, 100 overlap) → 123 chunks
    │
    ▼
Batch embedding generation (32 chunks at a time)
    │ Calls: https://bge-m3-llm.apps.ocp.7hrxw.sandbox880.opentlc.com/v1/embeddings
    │ Model: BGE-M3 (568M params, multilingual)
    │ Output: 1024-dimensional vectors
    ▼
Store in rag_documents with pgvector
    │ collection_id: iso-standards
    │ content: chunk text
    │ embedding: vector(1024)
    │ metadata: {language: "he", standard: "ISO9001"}
    ▼
Create IVFFlat index (100 lists, cosine similarity)
    │
    ▼
Ready for semantic search! ✓

Semantic Search Query
─────────────────────

User query: "דרישות ניהול איכות" (Hebrew: quality management requirements)
    │
    ▼
BGE-M3 generates query embedding (1024-dim)
    │
    ▼
PostgreSQL pgvector search:
    SELECT content, metadata,
           1 - (embedding <=> query_vector) as similarity
    FROM rag_documents
    WHERE collection_id = 'iso-standards'
      AND metadata->>'language' = 'he'
    ORDER BY embedding <=> query_vector
    LIMIT 10
    │ IVFFlat index scan: <50ms
    ▼
Top-10 relevant Hebrew clauses returned (total: <100ms)

Key Metrics
───────────

Model Performance:
  • GPT-oss-20b: P95 latency 2.3s, P99 3.1s, GPU cache 87%
  • BGE-M3: P95 latency 45ms, P99 67ms, CPU only
  • Qwen3-4B: P95 latency 1.8s, P99 2.4s (backup)

Extraction Accuracy:
  • Before (regex): 21/94 clauses (22% accuracy) ❌
  • After (GPT-oss-20b): 94/94 clauses (100% accuracy) ✓

Search Performance:
  • Embedding generation: ~45ms (BGE-M3)
  • Vector search: <50ms (IVFFlat index)
  • Total query time: <100ms

GitOps Deployment:
  • Full automation: 4 layers, sync waves
  • Auto-sync from Git: declarative, auditable
  • Rollback: git revert = instant rollback

Security:
  • Google OAuth + JWT authentication
  • MaaS gateway: rate limiting, RBAC
  • TrustyAI guardrails: HAP detection, content filtering
  • PostgreSQL: row-level security, audit logging
